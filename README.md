# Novel Writing Workflow

一个面向个人作者与 Coding Agent 的长篇小说 Git 仓库模板。正文使用 Markdown，少量状态使用 YAML；不绑定模型厂商，不调用模型 API，不兼容 Word。

## 开始使用

1. 在本仓库中启动具备文件读写能力的 Coding Agent。
2. 要求 Agent 先完整读取 `AGENTS.md`。如果工具不会自动识别该文件，必须显式告诉它读取。
3. 告诉 Agent“开始初始化小说项目”。
4. 与 Agent 依次确认文风指南、总纲和单卷或多卷结构；多卷作品还需确认相关卷纲。
5. 决定本轮先规划一章、连续若干章还是全书章纲。对应章纲确认后，才进入正文创作与审查闭环。

模板初始文件均为 `draft`，且不预置正文，避免把占位内容误认为已确认小说。

## 核心流程

```text
共同头脑风暴
→ 确认文风指南、总纲和单卷/多卷结构
→ 多卷作品确认当前卷卷纲；单卷作品由总纲兼任卷纲
→ 按用户选择起草并审查一章、多章或全书详细章纲
→ 用户逐篇或整批确认章纲
→ Agent 编写整章
→ 逻辑审查与修改
→ 逐句文风审查与修改
→ 跨章衔接审查与修改
→ 整章交付并创建 Git 检查点
→ 用户终审
→ 按用户要求发布
```

每类审查最多三轮。无法解决的创作分歧会交还用户裁决。

## 目录

| 路径 | 用途 |
|---|---|
| `outlines/` | 总纲、按需使用的卷纲和详细章纲 |
| `manuscript/` | 通过流程创作的章节正文 |
| `canon/` | 长期有效的人物、地点和世界设定 |
| `continuity/` | 时间线、当前状态和未解线索 |
| `style/` | 用户确认的文风指南 |
| `workflow/` | 当前流程状态和整章交付摘要 |
| `workspace/` | 不进入 Git 的临时草稿和完整审查记录 |

## 重要约束

- 章节全书连续编号，文件名只使用数字，不使用章标题。
- 单卷作品由总纲兼任卷纲，不保留独立卷纲文件；多卷作品使用相邻三卷卷纲窗口。
- 章纲可以按一章、连续若干章或全书推进，不强制与正文逐章交替。
- 正文创建前必须已有经用户确认的对应章纲。
- 用户直接修改的正文具有最高权威，不触发自动复审或同步。
- Git 记录整章交付检查点、用户确认点和长期有效产物，不记录内部草稿与中间审查。
- 详细执行规则以 `AGENTS.md` 为准。

## 可选发布

正文通过终审后状态为 `accepted`，不会自动公开。只有用户明确要求发布，正文才改为 `published`。

项目配置 `workflow/publication.yaml` 后，推送会把所有 `published` 正文同步到指定内容仓库。`published` 是持续生效的发布状态：保持该状态的正文以后再次修改并推送，也会更新公开副本；暂不希望公开修改时，应先改回 `awaiting_review` 或 `accepted`。
